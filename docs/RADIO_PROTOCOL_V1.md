# APEX Radio Protocol v1

## Invariants

- Every frame is exactly 32 bytes.
- Byte order is little-endian.
- Bytes `0..1` are ASCII `AX`; byte `2` is protocol version `1`.
- Bytes `4..5` are a wrapping uint16 sequence.
- Bytes `6..7` are a session ID generated by the authority at startup.
- Bytes `30..31` are CRC-16/CCITT-FALSE over bytes `0..29`.
- A raw C/C++ struct is never sent over the wire.
- nRF hardware CRC/ACK remains enabled; application CRC remains mandatory so
  recorded, UDP, serial, and SIL frames have the same integrity rules.

## Motion command (`type=0x10`)

| Offset | Size | Field | Unit/range |
|---:|---:|---|---|
| 0 | 2 | magic | `AX` |
| 2 | 1 | version | `1` |
| 3 | 1 | type | `0x10` |
| 4 | 2 | sequence | uint16 |
| 6 | 2 | session_id | uint16 |
| 8 | 1 | flags | arm, clear, gimbal, output-disable |
| 9 | 1 | mode | idle, manual-servo, gait, auto, calibration |
| 10 | 2 | joy_x | signed milli-scale `[-1000,1000]` |
| 12 | 2 | joy_y | signed milli-scale `[-1000,1000]` |
| 14 | 2 | joy_r | signed milli-scale `[-1000,1000]` |
| 16 | 2 | gait_z | millimetres `[-300,0]` |
| 18 | 2 | step_length | millimetres `[0,250]` |
| 20 | 2 | step_lift | millimetres `[0,180]` |
| 22 | 2 | cycle | milliseconds `[250,5000]` |
| 24 | 2 | body_pitch | centidegrees `[-3000,3000]` |
| 26 | 2 | body_roll | centidegrees `[-3000,3000]` |
| 28 | 2 | body_yaw | centidegrees `[-4500,4500]` |
| 30 | 2 | CRC16 | CCITT-FALSE |

The 50 Hz motion command is also the heartbeat. The receiver must not extend
the timeout for a duplicate, stale, invalid, or wrong-session frame.

Cross-language golden vector (`seq=1`, `session=0x1234`, arm requested, gait
mode, forward axis `+0.500`, all other fields at defaults):

```text
415801100100341201020000f40100009cff64003200e803000000000000ff6e
```

## Fast telemetry (`type=0x80`)

Fast telemetry returns link state, fault flags, acknowledged command sequence,
command age, IMU, ToF, two battery voltages, gait phase, mode, and radio quality.
It fits one 32-byte ACK payload.

## Leg telemetry (`type=0x81`)

One leg page carries current command-state, target, and home angles for three
joints in centidegrees. Pages rotate RF, RM, RR, LF, LM, LR. At 50 Hz each leg
is refreshed about 8.3 Hz without expanding the radio payload.

## nRF24 operating profile (initial)

- Base/Pi: PTX; robot/ESP32: PRX.
- Command frame at 50 Hz; telemetry returned in ACK payload.
- Dynamic payloads and auto-ack enabled.
- 5-byte addresses and 2-byte hardware CRC.
- Start at 1 Mbps; evaluate 250 kbps only when range testing justifies the
  longer air time and lower telemetry rate.
- Channel is selected only after a local 2.4 GHz survey; it is configuration,
  not a hard-coded protocol constant.
- RF24 retry timing must be selected together with ACK payload length. It is
  part of the link budget and tested under packet-loss injection.

Camera or LiDAR data is explicitly outside this protocol.
